# Skill: store architecture & editing rules

1. **Catalog is data, not code.** Products live in `data/catalog/<gender>/<category>.json`
   — one small file per category so a human can edit without a dashboard. The
   aggregate `data/products.json` is generated by `scripts/build-catalog.js`
   (`npm run catalog:build`, hooked to prebuild/pretest). Never hand-edit it.
2. **Schema discipline:** product fields are documented in `docs/ARCHITECTURE.md`.
   Adding a field means updating: category schema, build script, PDP/card usage,
   and the docs — in the same commit.
3. **Components in `src/components/store/`**, layout chrome in
   `src/components/layout/`, pure logic in `src/lib/`. Pages compose; they don't
   contain component definitions.
4. **Styles:** `tokens.css` (values) + `store.css` (system). Nothing else writes
   raw CSS for the storefront. Legacy `global.css`/`aasra-storefront.css` belong
   to legacy pages only.
5. **APIs keep their contracts.** `__aasra_addToCart`, `/api/checkout`,
   `/api/stock`, order-lookup, invoice: stable. If a change is unavoidable, update
   `tests/run.js` in the same commit.
6. **Every commit keeps `npm test` green and the build passing.**
