# AASRA Store — Playbook

The single guide to read before building a similar store. It records what was built, why, how to set it up from zero, how to add products, categories and sub-categories, how the storefront and client-side navigation work, where payments stand, and the mistakes already made.

- **Snapshot:** written against `main` at `eb7e511` (PR #90 merged), 2026-11-24.
- **Status words:** **Live** = on production · **Built** = in code and checked locally · **Parked** = in code, not approved for use · **Open** = needs a decision.
- **Names, not values.** Secret values live only in Cloudflare, GitHub Actions secrets, or local `.dev.vars` (never committed). The only real key-like value in the repo is a public Safepay key in `wrangler.toml`; it is not copied here.
- **Verification:** every file, script, name and number below was checked against the repo at this snapshot. Anything not verified is marked **Open** or left out.

Companion docs: `docs/ARCHITECTURE.md` (short reference for data model and routes), `docs/DESIGN_SYSTEM.md` (tokens, components, motion), `README.md` (backend reference; deposit text corrected, rest partly out of date), `CHECKLIST.md` at repo root (reference audit, not a feature list), `skills/*.md` (rules for editing).

## 1. What the product is

A code-only online store for AASRA, a handloom clothing brand for women and men in Pakistan. Customers shop in PKR and pay in full online (prepaid only). There is no admin dashboard: the catalog is JSON files, built into the site.

The design reference is an established luxury-fashion site, used for layout and feel only. Logos, copy, photos and product names are not reused.

## 4. Set up a similar store from zero

This is the order we would follow. Each step names the thing it depends on.

1. **Repo and Node.** Create the repo. Pin Node 24 with `.nvmrc` and `engines`. Ignore `node_modules/`, `dist/`, `.astro/`, `.wrangler/`, `.env*` and `.dev.vars` in `.gitignore`. Run `npm ci`.
2. **Dependencies.** `astro`, `wrangler`, `typescript`, `@astrojs/check`, and `@fontsource/cormorant-garamond` if the logo uses it. Use the versions in this repo's `package.json`.
3. **Cloudflare resources.** One Worker with static assets, one D1 database, and cron triggers. Copy the shape of `wrangler.toml`: `[assets]`, `run_worker_first = ["/api/*"]`, `[[d1_databases]]`, `[triggers]`, `[previews.vars]`.
4. **Database.** Create D1 with `npm run d1:create`, apply `migrations/` with `npm run d1:migrate`, and seed stock with `npm run d1:seed` if you need starting stock.
5. **Secrets.** Set them with `wrangler secret put` (names in §16). Never paste them into chat, a commit, or a shared file.
6. **Turnstile.** Create a widget. The site key goes in the build environment (GitHub Actions variable `PUBLIC_TURNSTILE_SITE_KEY`). The secret goes in Cloudflare as `TURNSTILE_SECRET_KEY`.
7. **Safepay sandbox.** Register the webhook URL `/api/webhook`. Keep sandbox and live keys separate. Start with `SAFEPAY_ENABLED` on and sandbox URLs (§11).
8. **Email.** Verify the sending domain in Resend. Add the DNS records. Check them with `nslookup`, because a "verified" badge is not proof.
9. **Domain.** Attach the custom domain in Cloudflare.
10. **Deploy from GitHub.** Add repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. The deploy workflow runs on push to `main` (§14).
11. **Run locally.** `npm run dev` (runs `prebuild` first). Run `npm test` before every commit.
12. **Catalog.** Create `data/catalog/site.json` and the category files (§5). Run `npm run catalog:build`.

## 5. The catalog (data model)

### 5.1 Site text: `data/catalog/site.json`
Keys include `brand`, `tagline`, `announcement`, `hero`, `marquee`, `nav` (per gender) and `footer`. Header and footer links are set here. Footwear is in both gender navs.

### 5.2 Category file: `data/catalog/<gender>/<category>.json`

```json
{
  "category": "footwear",
  "label": "Footwear",
  "subcategories": [ { "key": "boots", "label": "Boots" } ],
  "products": [ { "...product fields..." } ]
}
```

- `category` is the URL slug: `/women/footwear`. Lowercase, hyphens.
- `label` is the name shown on chips, tiles and headings.
- `subcategories` (optional). `key` is the URL slug: `/women/footwear/boots`. `label` is shown. Each product's `subcategory` must match one `key`, or the build fails.

### 5.3 Product fields

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | Unique. Our convention: `W` plus 3 digits for women, `M` plus 3 digits for men. |
| `slug` | yes | Unique. URL is `/product/<slug>`. |
| `name` | yes | Shown on cards, for example `Leather Derby — Brown`. |
| `price_pkr` | yes | Whole rupees. |
| `compare_at_pkr` | no | Original price, shown struck through. |
| `badge` | no | `"NEW"` puts the product in New In. |
| `subcategory` | yes, when its category has sub-categories | A `key` from the category file. |
| `colors` | yes (at least 1) | `[{ "name", "hex", "image" }]`. The first colour is the default. |
| `sizes` | yes (at least 1) | Each must pass the build's size check. |
| `images` | yes (at least 1) | Gallery photos in order. The first is the card photo. |
| `description`, `details[]`, `fabric`, `care`, `tags[]` | recommended | Product page copy. `tags` feed search. |
| `visible` | no | `false` hides the product. |
| `deposit_eligible` | — | **Legacy.** Ignored. Deposits were removed (§11). |

The build expands `sizes × colors` into `variants[]`, each with `sku` (for example `AS-<id>-<colour>-<size>`), `size`, `color` and `stock_key`. The bag, checkout and stock use SKUs. Do not rename SKUs after launch.

### 5.4 Build and checks
- `npm run catalog:build` writes `data/products.json` and `public/data/products.json`. It also runs before `build`, `dev`, and `test`.
- The build fails on: a missing `id`, `slug`, `name` or `price_pkr`; no sizes, colours or images; a bad size; or a `subcategory` not listed in its category file.
- Tests check products have images and variants, and that slugs and SKUs are unique.

## 7. Storefront behaviour

### 7.1 Header (`SiteHeader.astro`)
- Transparent over the hero at the top of the page, solid after scrolling.
- Hides when scrolling down, shows when scrolling up. The header sets `--as-header-h` so sticky bars sit below it. Do not hard-code the height.
- Mega menus open on hover after 180 ms intent, and on click for keyboard users.
- A mobile drawer (`#as-drawer`) and a search overlay (`#as-search`, input `#as-search-input`). The overlay fetches `/data/products.json` on first open and filters on the client.

### 7.2 Home
- **Hero** (`RunwayHero.astro`): full-screen carousel with scroll parallax. Dots only, no arrows. Advances every 6 s. Under reduced motion it stays on the first frame.
- **New In** sits above the Denim banner.
- **Denim:** full-width banner that fills the viewport height, then a carousel.
- **Categories in Focus** (`CategoriesFocus.astro`): full-height photo on the left, cards running off the right edge, one section, no in-section scroll.
- **Collection tiles:** on desktop, tiles and Categories fit one viewport. On phones the tiles are full-width and form a carousel.

### 7.3 Gender landing pages
- Hero, `CategoryStrip` (photo tiles; each link has class `as-cat-link`), `CategoriesFocus`, `FootwearFeature` (full-bleed footwear photo with CTA), and a footwear rail.
- Women's and men's pages have the same structure.

### 7.4 Category and sub-category pages (`CategoryPage.astro`)
- Breadcrumb: Home / Women / Category (/ Sub-category).
- Category chips for the gender.
- **Type chips** (second row) when the category has sub-categories: "All …" plus each type. Each type is a real URL (`/women/footwear/boots`), so it can be shared and works without JavaScript.
- Toolbar: **Filter** (colour and size, client-side), item count, and **Sort** with options Featured, Price low to high, Price high to low, and Name.
- Grid, plus an empty-state message.

### 7.5 Shop (`/shop`, `shop.astro`)
- The page is static, so **filters run in the browser** from the URL: `?category=footwear&type=boots&q=cable&sort=price-asc`.
- Chips and sort update the URL without a reload, so back and forward work.
- Type chips show only for categories with sub-categories.

**Lesson:** a static site reads the URL at build time only. Any filter written in frontmatter always sees an empty query. Put URL-driven filtering in the browser.

### 7.6 Product page (`/product/<slug>`, `[slug].astro`)
- **Desktop:** two columns. Photos on the left, details on the right. The details column is sticky.
- **Phone (up to 860 px):** the photos are a horizontal slider, with dots under the gallery. Tapping a dot scrolls to that photo. Dots follow the photo nearest the scroll position.
- Colour swatches: choosing a colour moves its photo to the front and resets to the first photo.
- A size must be chosen before adding. The sticky bag bar reads "Select a size" until then.
- The breadcrumb shows the sub-category when there is one.
- **Bag rules:** one click adds quantity 1. If the item is already in the bag, the button reads "Already in your bag — view bag" and does not add it again. The sticky bar reads "In your bag".

### 7.7 Cards, colour dots and quick-add (`ProductCard.astro`)
- Cards show photo, name, price and colour dots. Dots swap the card photo everywhere, including home and listings.
- Hover shows a quick-add size row. Clicking a size adds that SKU for the colour shown on the card.

### 7.8 Typography, colour, placeholders
- Headings Inter Tight, body Inter. No more than two typefaces.
- Error reds are fixed and not to be changed without a request: `#8a1f1f`, `#b00020`, `#8c2f2f`, `#7d2118`, `#9b2b1f`, `#9b3e32`, `#fdf3f1`, `#fbf3f3`.
- **Placeholders:** product, colour, denim, footwear and product-page photos are placeholders until the owner sends final images. Sample products are treated as real: no "Sample" labels.

## 8. Bag (cart)

- Storage: `localStorage` key `aasra_cart_v1`, an array of `{ sku, name, price, qty, image }`.
- Helpers defined in `StoreLayout.astro`: `window.__aasra_addToCart(sku, name, price, qty, image)`, `__aasra_updateQty(index, delta)`, `__aasra_remove(index)`.
- Events: `aasra:cart` (bag changed) and `aasra:cart:clear`. The header count and other pages listen to these.
- After an add, the "Added to your bag" panel (`#as-added`) appears with **View bag**, **Check out** and **Continue shopping**.
- **Open decision:** the cart quantity fix needs an owner decision (§18). Do not change its behaviour without asking.

## 9. Client-side navigation (no full reloads between browse pages)

**What it is:** Astro's `ClientRouter` swaps page content without reloading the site. The header, footer and bag panel stay in place. This made moving between categories, sub-categories and products faster (PR #90).

**Which pages:** pages that pass the `spa` prop to `StoreLayout`: `/`, `/women`, `/men`, `/shop`, the category and sub-category pages, and product pages. Cart, checkout, order, payment and policy pages use a normal full load.
- **Open:** whether `checkout`, `pay-balance`, `order-lookup` and `order-success` should stay full loads. The code uses full loads; the decision is not recorded. Links from the storefront into them are not yet browser-tested.

**How it's switched on:** `StoreLayout` renders `<ClientRouter fallback="swap" />` only when `spa` is set. Pages without `spa` load normally.

**Rules for page scripts (the important part):**
1. **Initialise on `astro:page-load`**, and also call the init function once at load. The event fires on first load and after each client navigation.
   ```js
   const init = () => { /* look up elements, attach listeners */ };
   init();
   document.addEventListener('astro:page-load', init);
   ```
2. **Look up elements inside init**, never at module top level. The old elements are gone after navigation.
3. **Window and document listeners** must not stack up. Remove them before re-adding, or use a cleanup function. The product page does this with `window.__pdpCleanup`.
4. **Persistent chrome** uses `transition:persist` on its root element: `header#as-header`, `div#as-drawer`, `div#as-search`, `footer.as-footer`, and `aside#as-added`. Persist on the component tag did not keep the mega menus working; persist on the root element did.
5. **Inline scripts with `define:vars`** use `data-astro-rerun` so they run on every page (as in `[slug].astro`).
6. **Header state per page** (menus closed, header shown) is reset on `astro:page-load`.
7. **Test it:** set `window.__mark = 'alive'` before a click, then check the value is still there afterwards. That proves no full reload. Also test back and forward.

Astro's `popstate` handling covers back and forward, so no custom back-button code was needed.

## 10. Design system (short version)

Full detail in `docs/DESIGN_SYSTEM.md`. The rules that matter most:
- **Tokens only.** Colour, type, spacing, radius and motion come from `src/styles/tokens.css`. No literal values in components.
- **Motion budget:** one signature interaction per section; everything else is a short hover. Reduced motion always wins.
- Touch targets at least 44 px. Visible focus rings. Real alt text.
- No gradients, glass effects or emoji. Two typefaces at most.
- Edit the file that owns the style. Do not add override stylesheets or `!important` fixes.

### 10.1 CSS gotchas we hit
- **Global rule** `main a:not([class*="as-"]):not(.btn)` in `store.css` sets unclassed links to inline-block. Fix: give the link a class starting with `as-`.
- **HTML `height` on images** overrides the CSS aspect ratio. Set `width` and `height` in the ratio you want, or set neither.
- **Sticky on phones:** use `position: sticky; top: 0` for the hero parallax container, not `relative`.
- **Carousels:** carousel scrollbars are hidden; other carousels keep arrows.

## 11. Checkout and payments

### 11.1 Decisions
- **Prepaid only.** Customers pay in full online. The deposit option was removed. Checkout accepts only `payment_type=full` (`functions/api/checkout.js`).
- **No cash on delivery** (stated in the footer copy, `Footer.astro`).
- Pakistan only, PKR, whole rupees.
- **Free delivery threshold: PKR 20,000.** It is the same in the header announcement, home, cart drawer, cart page copy and FAQ. Keep it that way if the value changes.

### 11.2 Flow
1. Customer checks out (`POST /api/checkout`). The server validates the cart, prices it, adds tax (`TAX_RATE_PCT`), and reserves stock for **15 minutes** (`reserveStock`, default hold 15).
2. The server creates the Safepay checkout session and the order number `AAS-YYYYMMDD-XXXX`.
3. Customer pays on Safepay and returns to `/api/safepay-return`.
4. Safepay calls `POST /api/webhook`.
5. The order is marked paid only when the webhook or reconciliation shows `TRACKER_ENDED` **and** the amount matches our record.
6. The receipt email is sent (Resend). The order lookup page shows status.

### 11.3 Webhook and verification (from Safepay's SDK, `getsafepay/safepay-python`)
- Signature: HMAC-SHA512 hex over the **raw** request body, sent in `X-SFPY-SIGNATURE`. Verify before parsing.
- Payload fields: `token`, `type`, `data.tracker`, `data.state`, `data.amount`, `data.currency`, `data.metadata.order_id`. The SDK names `payment.succeeded` and `payment.failed` as the event types.
- Fetch a payment: `GET /reporter/api/v1/payments/{tracker}` with header `X-SFPY-MERCHANT-SECRET`.
- Settled means `state == TRACKER_ENDED`.
- **Duplicate guard:** a second full payment for the same order is recorded as `duplicate` and flagged `refund_required`.
- **Reconciliation** (`functions/lib/reconcile.js`) catches missed webhooks. Cron schedules are every 15 minutes and daily at 09:00 UTC (`wrangler.toml`).
- Sandbox base URL is set in `wrangler.toml`. A comment there says sandbox serves API and checkout from one host, and gives the live checkout host. Confirm against Safepay's docs before going live.

### 11.4 Rules we set
- **Never mark an order paid by hand.** That was requested once and rejected. Fix the webhook path.
- Sandbox test cards come only from the gateway's own docs or dashboard. Never use real cards.
- The live switch is **not approved**.

### 11.5 Status
- **Built:** checkout, webhook, return page, lookup page, reconciliation, duplicate guard, receipt email.
- **Sandbox orders:** `AAS-20261122-SRQP` and `AAS-20261122-CATP` were created. `SRQP` is still pending. For `CATP` the webhook result was not confirmed. **An end-to-end PAID test order with receipt and lookup showing PAID is still the goal.**

## 12. Email

- Provider: Resend (`EMAIL_PROVIDER = "resend"`, implemented in `functions/lib/email.js`). API key: secret `EMAIL_PROVIDER_API_KEY`.
- Sender: `EMAIL_FROM` and `EMAIL_FROM_NAME` on the verified domain `aasra.shop`.
- **Receipts** must show Paid, order number, items, quantities, prices, totals, shipping and business details. Missing details block launch.

- Free-tier limits quoted by third parties (Oct 2026): 3,000 emails a month, 100 a day, 3 domains. Check Resend's pricing page before budgeting.

## 14. Deployment

- **On push to `main`:** `.github/workflows/deploy.yml` runs `npm ci`, `npm run build`, then `npx wrangler deploy`. It needs `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
- **Before merging a change to `functions/`:** run `npx wrangler deploy --dry-run --outdir /tmp/wdry`. A failed workflow re-run (`gh run rerun`) did not work for us; push a fresh commit instead.
- **Previews:** non-production branches use `[previews.vars]` in `wrangler.toml`. Those preview vars set Safepay to disabled, so previews do not take live payments.
- **Local preview:** `npm run build`, then `python3 -m http.server 8792 --bind 0.0.0.0 --directory dist`. You get 404s if `dist/` is missing.
- **Cache:** when someone reports "no change", ask for a hard refresh or a private window first. That fixed every such report we had.

## 15. Testing and QA

- `npm test` (46 checks). `pretest` rebuilds the catalog first. Importing `functions/api/checkout.js` from a test fails, so guard tests read the source.
- `npm run smoke` runs `scripts/smoke-worker.mjs`. `scripts/safepay-smoke.js` checks the gateway.
- `npm run typecheck` runs `astro check`.
- **Browser checks** (what we used):
  - `puppeteer-core` with `@sparticuz/chromium` in a scratch folder outside the repo. Chromium needed Amazon Linux shared libraries; they were extracted to a local path and set through `LD_LIBRARY_PATH`.
  - Check at 390×844 (phone) and 1280×900 (desktop).
  - Wait for the network to go idle. Scroll before capturing: reveal-on-scroll elements stay hidden until scrolled into view.
  - Check `img.naturalWidth > 0` after scrolling. Full-page screenshots can be taken before lazy images load, which looks like missing photos.
  - Write each check to a file and run it. Inline scripts failed silently for us.
  - Listen for `pageerror`. Google Fonts requests fail in a sandbox with no internet; ignore those.
- Look at a screenshot before saying something is fixed.

## 17. Git and pull-request workflow

- One branch per request, named by the session (`arena/<id>-aasra`). Commit and push only to that branch. Open one PR per change into `main`.
- **Merge only on an explicit "merge" from the owner.** Each PR needs its own approval. Use `gh pr merge <n> --merge` without `--auto`, and confirm the state with `gh pr view`.
- **Never commit** `data/products.json` or `public/data/products.json`. Stage files by name, not `git add -A`.
- Fix history with `git reset --soft` or a new commit. Do not force-push shared work.
- `gh pr create` on a branch with an existing PR returns that PR. Run `gh pr view` first.
- After `gh pr edit`, GitHub can keep the old title. Check it.
- In a shallow clone, `git diff <sha>^1` can fail. Run `git fetch --deepen=3 origin`.
- **Session resets:** `/tmp` scratch folders and `node_modules` can disappear. Re-run `npm ci`, then rebuild the scratch browser tools (§15) before testing.

## 20. Pitfalls already hit (check these first)

| Symptom | Cause | Fix |
|---|---|---|
| Filter, sort or search does nothing on a static page | URL read at build time | Filter in the browser from `location.search` (§7.5) |
| Page works on first load, breaks after a click | Script ran only once | Initialise on `astro:page-load` (§9) |
| Mega menu or search dead after navigation | Persist set on the wrong element | `transition:persist` on the root element (§9) |
| Strip links tiny | Global `main a:not([class*="as-"])` rule | Give the link an `as-` class (§10.1) |
| Build fails under Node 22 | Wrong Node | Use Node 24 (`.nvmrc`) |
| Build fails with `astro: not found` | `node_modules` missing | `npm ci` |
| Product photos look missing in screenshots | Lazy images not loaded yet | Scroll, then check `naturalWidth` |
| "No change" after a deploy | Browser cache | Hard refresh or private window |
| Sticky element jumps on phones | `relative` used instead of `sticky` | `position: sticky; top: 0` |
| Product page says "Already in your bag" | Intended behaviour | Not a bug |
| Lookup page shows "Network error" | `can_pay_balance is not defined` | Fixed. Do not switch the lookup back to GET. |
| Preview 404 | `dist/` missing after a reset | `npm run build`, then start the server |
| Node 22 build error | Wrong Node | Use Node 24 |
