# AASRA — Known issues (audit at snapshot `eb7e511`)

Defects and gaps found by reading the code against the docs. **None of these is fixed by the documentation change.** Each needs its own approved change, and changes to payment, order or email code need the owner's approval and a dry-run deploy (see `PLAYBOOK.md` §14).

**Severity:**
- **High:** affects money, tax, or customers now. Fix before live payments or before reuse.
- **Medium:** wrong or missing behaviour that will bite under normal use.
- **Low:** hardening, clean-up, or a rare case.
- **Info:** a decision recorded so it is not made by accident.

## Resolved in this codebase (for reference)

- Deposit option removed; checkout rejects `payment_type` other than `full`.
- Checkout no longer returns a fake payment URL when Safepay is not configured.
- Duplicate full payments are recorded and flagged, not settled twice (commit `f53b0ed`).
- Order lookup crash `can_pay_balance is not defined` fixed (commit `5fe1fb0`).
- Lookup takes the phone in the POST body (commit `5cb4851`).
- Stock is no longer lost on failed checkouts (PR #30).
- Safepay webhook field mapping fixed so paid orders settle (PR #38).
- Money invariant check fixed for full payments (PR #27).
